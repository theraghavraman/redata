## Manual license review

### Source archive contents

The Git tree for the release commit contains no wheel, shared-library, DLL, executable, ZIP, or tarball artifacts. The local-engine launcher installs the declared dependencies from PyPI into a private virtual environment; those third-party binary distributions are not bundled in the ReData source archive. The GitHub release has no attached assets.

The source-only release therefore does not itself redistribute the audited Python wheels. The following terms must nevertheless remain visible in notices and be reviewed again before any future packaged/binary distribution:

- `psycopg==3.3.6` and `psycopg-binary==3.3.6`: LGPL-3.0-only. Psycopg's binary extra is self-contained and includes client libraries.
- `pymssql==2.4.4`: LGPL-2.1-or-later. Upstream documents that official wheels bundle a static copy of FreeTDS. The SBOM normalization is based on the upstream LGPL-2.1-or-later text; it is not legal approval of a future bundled binary.
- `certifi==2026.7.22` and `fqdn==1.6.0`: MPL-2.0.
- Other resolved license expressions include Apache-2.0 OR BSD-3-Clause and Apache-2.0 OR BSD-2-Clause. The exact resolved inventory should accompany future packaged builds.

Upstream references reviewed:
- [pymssql 2.4.4 on PyPI](https://pypi.org/project/pymssql/2.4.4/)
- [pymssql source repository](https://github.com/pymssql/pymssql)

## Security finding discovered after v0.1.0 publication

The manual browser dependency review found that the released v0.1.0 `index.html` references `xlsx@0.18.5`. SheetJS's official advisory states that all SheetJS Community Edition versions through 0.19.2 are affected by CVE-2023-30533 when reading specially crafted files; the issue is fixed in 0.19.3 and later. ReData reads user-supplied spreadsheet files, so this was relevant to the app's import path and was not detected by the Python-only `pip-audit` step.

- [Official SheetJS CVE-2023-30533 advisory](https://cdn.sheetjs.com/advisories/CVE-2023-30533)
- [SheetJS official standalone browser scripts](https://docs.sheetjs.com/docs/getting-started/installation/standalone/)

The fix has been committed to main: the worker now loads the official SheetJS 0.20.3 browser build, and SQL.js was updated from 1.8.0 to 1.14.2. A browser dependency workflow now checks the pinned versions, license notices, inline JavaScript syntax, and CDN asset reachability. Its passing run on the patched code and updated notices is https://github.com/theraghavraman/redata/actions/runs/38242324149.

**This fix does not alter the already-published v0.1.0 tag.** Do not describe v0.1.0 as fully security-cleared. The appropriate path is a new patch release after the full checks pass on one exact candidate commit. No new release or tag was created by this audit.

The follow-up documentation and CI-trigger changes are now on main. The resulting untagged head must be treated as a fresh patch candidate: wait for dependency audit, browser dependency audit, citation validation, regression/benchmark tests, and Pages deployment to finish on that exact head before creating any new tag. This report does not certify a v0.1.1 release.

## Decision

- **v0.1.0 source identity, citation validation, Python dependency audit, and listed CI checks:** verified.
- **Source-archive license review:** acceptable with the documented LGPL/MPL and future-packaging caveats; no third-party Python wheels were bundled in the source archive.
- **Security status of v0.1.0:** known browser dependency issue found post-publication; a fix is on main, but the existing tag remains unchanged.
- **Next release:** do not publish or confirm a new version until browser dependency audit, Python dependency audit, citation validation, correctness tests, benchmark workflow, and Pages deployment are green on the same candidate commit. Include the version-specific DOI and the audit evidence in the next release notes/assets; the current v0.1.0 GitHub release text still says the DOI is pending and needs manual correction if the release description is edited.
- **Research-evaluation claims:** remain unapproved. The 10-million-row historical benchmark has not been reproduced for this release, browser-only operations have not all been independently tested, and no independent reproduction has been established.
